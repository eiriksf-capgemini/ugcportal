## 2. Decisions and why

### The product pivot is the frame for everything else

Instagram is deferred, not cancelled. Two decisions, in order: `2eh` found Meta's Platform Terms
§3.a.iv prohibit selling Platform Data, so the API became discovery-only and the sellable asset
became the owner-uploaded original — which already made uploads the centre. Then the remaining API
value did not justify the OAuth, token-refresh, deauthorize-callback and sync work in front of it,
so six beads were deferred **with their specs intact** rather than closed.

Consequence you will meet in the code: several things were built against a model that is no longer
the product's centre. `ResaleRightsReview` hangs off uploads now (`vsm` re-anchored it), but the
checklist it implements was written for Instagram accounts, which is what `9cs` is about.

### Why the gallery has no per-category sections

Eirik's call, and it should not be relitigated: *"if we only have 1 with 1, 1 with coffee and 15
with food then there will be a graphical mishap. I want a picture to have a tag somehow that's
visible on all elements, but in general I don't want silos with different categories."* `jsc`
delivers tags as a property of each item in one unified gallery. In-place filtering was
**decided against**, not forgotten — `8rm` records it as a decision.

### Why the tag picker shows only curated tags

`jsc` round 1 bounded the picker to the 24 oldest tags. Round 3 found that was the same defect one
level down: only four subjects are seeded, so slots 5–24 were free, first-come, and **permanent**,
because nothing in the product deletes a tag. A `curated` flag was chosen over a delete path for a
specific reason — `_MediaToTag` cascades, so deleting a `Tag` strips that subject from every item
pointing at it, **including other people's published work**. Un-curating is reversible; deleting is
not. `x0l` now asks only *who may curate*.

### Why sign-in is closed by default rather than allowlisted a particular way

`egp` shipped the gate; it did **not** pick the rule. `ALLOWED_SIGNIN_EMAILS` ∪
`ADMIN_BOOTSTRAP_EMAILS` behind a seam (`decideSignIn` / `permittedIdentities` / `authorisedEmail`
in `src/lib/sign-in-policy.ts`) so swapping in an invite system or a domain rule is a local change.
The default is refuse, because the entire defect was that open was the default.

### Why the stopping rule gates on severity rather than round count

Measured, not assumed: review value decayed **unevenly**. One bead's round 7 found a live
fail-open (`NaN <= number` is false, so an Invalid Date skipped the expiry check entirely); another's
round 9 found a migration minting 32-char hex where the runtime minted 36-char dashed UUIDs for the
same public id column. A third bead's rounds 8 and 9 found an inaccurate comment and duplicate log
lines. A flat cap cannot tell those apart — that is the whole argument, and `2yj`'s original
framing ("a five-round cap would have kept funding the one that wasn't earning") is weaker than the
real one.

## 3. Dead ends — things tried and abandoned

**Do not retry these without new information.**

- **Timestamp-clustering to infer review rounds** (`2yj`, rounds 1–2). Counting comment bursts to
  derive which round a PR is on. Deleted, because every measurement validating it was taken
  retrospectively on finished PRs, where the in-flight round's own artefacts do not exist. Replaced
  by a marker the skill stamps and reads. The lesson generalises: *a guess about another agent's
  behaviour loses to a fact you write down.*
- **An author filter as forgery defence** (`2yj`, round 2). Abandoned after measuring that
  `gh api user` and the PR author are the same account, so the filter protects nothing here. It is
  still in the command (one field, starts working under a separate bot identity) but it is
  explicitly **not** load-bearing, and the skill says so rather than implying otherwise.
- **Request middleware to supply the current path** (`t0y`, round 3). `src/proxy.ts` was added
  because the App Router gives a root-layout component no first-class way to read the current path.
  Deleted in round 4: the matcher also matched `/api/*`, and Next clones the body of any
  proxy-matched request via `getCloneableBody`, **truncating at 10 MB with only a `console.warn`**.
  This app accepts 200 MB videos. It also did not work — the root layout is not re-rendered on soft
  navigation, so `aria-current` never updated on click. `usePathname()` in a client component does
  both jobs with no request-level machinery.
- **Tracking created-versus-found tag slugs as a compensating delete** (`jsc`, round 3). Rejected
  because a concurrent upload that attached the same new subject in between would silently lose it.
  One transaction instead.
- **`vitest` `include:` narrowing** (`97y`). Added then removed after review found it a silent-drop
  hazard — a new test directory would simply stop being collected. `exclude` only.

## 4. Claims in the repo you should re-check before trusting

This project's most expensive recurring defect is **a comment claiming a guarantee the code does not
make**. These are the ones known to have been wrong and corrected; treat them as evidence about the
class, not as a complete list.

- Three separate descriptions of `src/lib/auth.ts`'s sign-in mechanism were wrong before one was
  right. **Before `egp` merged** there was no `signIn` *callback* at all — only an `events.signIn`
  hook, whose return value `@auth/core` discards, so the `return false` the bead told an
  implementer to add would have compiled, run and refused nobody. `egp` added the callback, so the
  merged tree now has both: `callbacks.signIn` and `events.signIn`, and you should read them rather
  than trust a line number here.

  This bullet is itself the fourth version. The first three drafts stated the pre-`egp` fact in the
  present tense with a line number attached, and review caught it again *in this document*, in the
  section warning about exactly that. Tense is load-bearing when a document outlives the tree it
  describes. `@auth/core`'s `defaultCallbacks.signIn()` returns `true`, and
  `handleAuthorized` throws `AccessDenied` on any **falsy** return while reading a **string** as a
  redirect URL. Two of those three wrong descriptions were written by the orchestrator, into a P0
  bead, and read as verified *because they cited a file and a line*. The line number was correct.
- `not.toContain("disabled")` was described as an assertion that passes in both directions. It is
  the **positive** `toContain("disabled")` that always passes, because every Button ships
  `disabled:pointer-events-none disabled:opacity-50` in its class list. The backwards version
  propagated three times downstream before a reviewer ran `git log -S` and established the negated
  form never existed in this repo.
- `2yj`'s own premise says "nine implementation rounds and eight review rounds". Counted from the
  beads' merge notes the real worst case is **ten and nine** (`r1d`).

## 5. Open questions — genuinely undecided, and whose they are

**Eirik's, and they block real work:**

1. **Is this a marketplace or a portfolio?** `p3v` is a single-seller checkout; `137` (creator
   profiles) assumes many creators. With one creator, `137` is an About page. This also decides how
   `egp` finally closes and whether `lb8` (likes) means anything — a like count over the handful of
   accounts an allowlist permits measures nothing.
2. **Does `3ae` gate the v0.4.0 tag?** Publishing is completely ungated by the rights review —
   verified directly, and it is *documented as deliberate* in `publish/route.ts`: publishing is "a
   visibility switch and nothing else". That separation is right for money and wrong for privacy,
   because åvl § 104 and GDPR bite at publication rather than at sale. Nothing is deployed, so
   there is no exposure today.
3. **Ratify `9cs` §8** — including a row asking you to accept a scope extension into Part E that
   the bead had declared out of scope. `fw5` cannot start until this is answered.

**Open and nobody's yet:**

- `lju` (share + OG tags) has **no item page to share a link to**. At the time of writing `src/app`
  had six `page.tsx` files and eleven `route.ts` handlers, and none of them addresses a single
  media item — re-check with `find src/app -name page.tsx` rather than trusting the count. Either build per-item routes or deep-link into the gallery and server-render OG
  tags per param — decide before starting, it is two different beads.

## 6. Deliberate non-goals

Things that are **not** being done, on purpose, so nobody helpfully does them:

- **Reducing review depth to save money.** This is `9ak` K5 and it is a guardrail, not a
  preference. The reviews in this phase found a command injection, a permanent operator
  self-lockout, an unbounded globally-writable tag vocabulary, and the P0 open-signup hole. Cost
  work may change what a round *costs*; it may not remove a round, lower a reviewer's tier, or
  narrow the three-family sweep without a separate decision from Eirik.
- **Instagram integration.** Six beads deferred with specs intact. Do not revive them as a
  side-effect of touching adjacent code.
- **Video watermarking** (`pmb`). Needs ffmpeg (~80 MB) in an image whose musl `sharp` binding is
  itself still unverified. Blocked on `s8w` (playback), and `dzz` blocks it too — the gallery does
  not branch on `kind`, so a published video would render as a photograph.
- **Working around `.claude/settings.json`'s deny rule.** It exists because an agent once
  self-modified it inside a work branch and nearly got it auto-merged. If a task needs it, hand the
  diff to Eirik.
- **Per-request session revocation** (`mzr`). Deliberately *not* smuggled into `egp`:
  `callbacks.session` returns `Awaitable<Session | DefaultSession>` with no "deny" to return, so
  denial would have to move into `auth()`'s consumers or middleware. That is a design decision with
  a per-request cost, and a `maxAge` is a third option with a UX cost.

## 7. Two operational facts that will bite

1. **`egp` is merged but the hole is not closed.** Pre-existing 30-day database sessions bypass the
   new gate entirely. `DELETE FROM Session` has to run on the deploy that carries it. And
   `ALLOWED_SIGNIN_EMAILS` must be set **before** deploying or nobody can sign in, including Eirik.
   Runbook: `docs/access-control.md`. When purging, do **not** delete `User` rows — the transitive
   `onDelete: Cascade` closure from `User` is seven tables (fewer are *direct* relations; the rest
   arrive through `Media` and `MediaListing`), including one that destroys upload records while
   leaving the bucket objects orphaned. The runbook enumerates all seven and
   `src/lib/access-control-doc.test.ts` parses the schema to keep that table honest, so trust the
   test over this sentence.
2. **Nothing in the media path has ever run against live storage.** Upload → store → watermark →
   gallery has only ever been exercised with S3 mocked. Every agent that built a piece of it flagged
   the same gap and none could close it: no `.env`, no MinIO credentials. That is `321`, labelled
   `human-only`. A green CI run on v0.4.0 does not mean a photograph has ever reached a gallery tile.

## 8. Working-practice notes for the next session

- **Name the model on every worker-shaped spawn.** The built-in `general-purpose` type has no
  definition file and therefore **inherits the parent's tier**. Measured: 5,955 subagent requests
  ran on Opus where Sonnet was specified — $539, 35% of the period's spend, as pure arithmetic.
  `9ak` and the `worker-shaped-subagent-spawns-must-name-their-model` memory have the detail.
- **Keep the session small.** Cost is rent on context: a request at >700k costs **22×** one at <50k
  for the same output. This session reached 967k and is 90% of the project's spend. That is why it
  is being cleared rather than continued.
- **Do not park a large session.** The 5-minute cache TTL expires while idle and the whole context
  is rewritten at 1.25×; a >1h gap cost $2.31/request in cache writes alone.
- **Run `npx prisma generate` before trusting any test count**, and treat a collected *file* count
  dropping without a test being deleted as the symptom of a broken worktree — not as a real number.
  This has produced wrong counts five times.
- **Verify a consequence; do not infer it.** Twice this session a confident structural hypothesis
  about a change was wrong — once causing a correct fix to be discarded and redone, once nearly
  causing it. Both times a two-minute check settled it.
